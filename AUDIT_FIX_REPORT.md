# Bagheri CRM — Verified Bug Fix Report

Date: 2026-09-01

## Verified and fixed

### F-001 — Reason Code persistence
- Status: VERIFIED → FIXED
- Root cause: `normalizeData()` did not copy `reasonCodes` from persisted data, so reload/restore rebuilt the dataset without them.
- Fix: preserve supported Reason Code fields during normalization; legacy backups without the field remain valid.
- Verification: normalization runtime test + existing Reason Code regression suite.

### F-005 — Strategic Product persistence
- Status: VERIFIED → FIXED
- Root cause: product normalization omitted `strategic`.
- Fix: preserve only the explicit boolean `strategic === true`; legacy products default safely to `false`.
- Verification: true/false/legacy normalization runtime test + Intelligence regression suite.

### F-002 — Return Profit Cost Basis
- Status: VERIFIED → FIXED
- Root cause: return stock logic already derived the actual FIFO return slices, but the return record did not persist that cost basis; profit calculations reconstructed cost from `buyPrice`/`product.buy`, which can differ from the actual FIFO allocation.
- Fix: persist the exact return `costAllocations` generated by the existing return/FIFO path and consume that allocation in customer and command-center profit calculations. No second FIFO engine was introduced.
- Verification: multi-layer FIFO return runtime test and profit calculation test.

### F-003 — Undo Restore incomplete system state
- Status: VERIFIED → FIXED
- Root cause: pre-restore snapshot covered CRM (and Prospect separately) but not Intelligence, Game Center, or Sales Target.
- Fix: composite pre-restore system snapshot covering CRM, Intelligence, ProspectScout, Game Center, and Sales Target. Undo restores the captured state with compensation rollback on failure.
- Verification: composite snapshot/helper runtime test; source/data-flow verification.

### F-004 — Legacy backup leaves stale Intelligence
- Status: VERIFIED → FIXED
- Root cause: restore only replaced Intelligence when `intelligenceState` existed. Legacy backups could therefore leave Intelligence belonging to the previous dataset.
- Fix: legacy restore deterministically clears Intelligence state instead of retaining incompatible context.
- Verification: deterministic invalidation helper test and source-level restore-flow verification.

### BKP-002 — Game Center missing from Full Backup
- Status: VERIFIED → FIXED
- Fix: Full JSON and automatic backups now include Game Center `gameMeta` and `gameLedger`; restore/undo paths restore them.
- Verification: backup export and state helper runtime tests.

### BKP-003 — Sales Target missing from Full Backup
- Status: VERIFIED → FIXED
- Fix: Full JSON and automatic backups now include Sales Target and restore both its localStorage and IndexedDB representations.
- Verification: export/restore helper runtime tests.

### OFF-001 — Intelligence/Reason Code App Shell precache
- Status: VERIFIED at source/static level → FIXED; real Safari first-install offline behavior remains environment verification.
- Root cause: required Intelligence modules and `reason_codes.js` were loaded by `index.html` but absent from Service Worker precache.
- Fix: added all required Intelligence/Reason Code modules and bumped shell cache version to v33.
- Verification: all 61 precache URLs exist and return HTTP 200 from a local HTTP server. A real iOS/Safari first-install → offline test was not available in this environment.

### INT-001 — local midnight timestamp boundary
- Status: VERIFIED → FIXED
- Root cause: persistence date extraction used `slice(0,10)` on UTC ISO timestamps, which can classify events shortly after local midnight as the previous local date.
- Fix: full timestamps are converted to local calendar date before extracting the business date; date-only values remain unchanged.
- Verification: Europe/Amsterdam midnight-boundary runtime test.

### FIN-002 — Profit Preview labeling
- Status: VERIFIED → FIXED
- Root cause: invoice-entry profit preview uses the current weighted-average open FIFO inventory cost, not the final allocation that will be consumed by the completed sale, while the UI label said simply “based on FIFO”.
- Fix: label now explicitly identifies the figure as an estimate based on current average FIFO inventory cost; line-level preview is also labeled approximate.
- Verification: source/data-flow inspection.

## Not patched

### BKP-004 — Semantic backup validation
- Status: NEEDS VERIFICATION
- Current validation correctly requires the core backup arrays, but a deeper semantic validator (orphan references, duplicate IDs, invalid dates/numbers) was not added because doing so without a corpus of accepted legacy backups could reject valid historical data. No runtime corruption scenario was established that justified a broader validator in this patch.

### PROS-001 — ProspectScout / CRM separate databases
- Status: NOT REPRODUCED as a material bug
- The conversion flow is explicitly idempotent: if CRM creation succeeds before Prospect persistence, retrying finds/links the existing customer; exact-name duplicate prevention also reuses an existing customer. No distributed transaction architecture was introduced.
